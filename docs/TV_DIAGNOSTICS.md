# Samsung / LG opt-in diagnostics

`POST /api/tv/telemetry/events` accepts anonymous JSON only, maximum8KB /10events. Cookies, Authorization and API-key headers are rejected. Public CORS applies to this exact POST/OPTIONS path only, including opaque nativeTV origins. No client secret is required or embedded.

The closed contract is in `artifacts/api-server/src/lib/tv-diagnostics-policy.ts`. Each batch identifies platform (`tizen`/`webos`), package semver, verified-form bundle version and explicit booleans `consent.diagnostics` / `consent.analytics`. Defaults in clients must be OFF. Diagnostic events require diagnostics consent; usage events require analytics consent. Screen names and codes are fixed enums. Optional module/line/column locate bundled script failures without accepting filenames, messages, stacks or source URLs. Unknown fields fail validation. No account/device identifier, QR code, search text, station name, stream URL, user agent or IP is persisted.

Admission uses20requests/minute per address in a bounded transient memory throttle (10,000buckets, expired every minute), with identical reports coalesced during that minute. At most32writes can be pending perprocess. Responses:204accepted/coalesced,400invalid/unconsented,403credentialed,413oversize,429limited,503storage unavailable. Failed writes may be retried with bounded client backoff; reporting failure must never affect playback.

Migration0046creates daily counters only. A database advisory transaction lock enforces at most4,096dimension groups/day across replicas; new groups beyond budget are dropped, existinggroups can increment. Counters saturate safely. Thirtycalendar days are retained via existingTVcleanup everyminute and a bounded hourlyprune during writes; previousboot history is not deleted beyond its oldretention. Previousboot endpoint remains compatible but no longer ingests persistent`did` and accepts actualGHAversions.

`GET /api/admin/tv-diagnostics` uses existing `requireAdmin`, validates1–30days and optionalplatform, returns at most2,000groups. Admin page `/admin/tv-diagnostics` explicitly presents opt-in event counts, never uniqueusers, nativecrash-free rates or ANRs. No reports is not evidence of nofailures. Offline, terminated-native-process and disabledconsent cases are not observable.

The optional GA4 Measurement Protocol relay is disabled without both server-only `TV_GA4_MEASUREMENT_ID` and `TV_GA4_API_SECRET`. The existing Web stream is verified, but no secret exists; accepting Google terms and creating/configuring it requires the owner's approval. Only usage-consented, usage-only batches may include a separately random pseudonymous `analytics.clientId`, runtime `sessionId` and measured `engagementTimeMsec` (0–600,000). Diagnostics with identifiers are rejected; metadata is stripped before calling persistence. It is neither a user/account identifier nor the old persistent device ID. Clients delete it upon usage opt-out.

The relay uses official HTTPS endpoints only, no queue, retries, disk spool, custom IP/location, user properties, raw URLs or secret logging. Up to four operations may run for at most two seconds. An actual opted-in payload is first validated via `/debug/mp/collect` with `ENFORCE_RECOMMENDATIONS`; only an empty validation error list permits `/mp/collect`. Debug responses are capped at 16KB; failures block collection, validation errors cool down five minutes. Successful configuration validation is cached for the process. Measured batch engagement is attributed once, not repeated across every event. Ad user data and ad personalization are explicitly denied. Admin exposes configuration and payload-validation booleans only. HTTP2xx is receipt, not proof of GA4 processing; no real events have been sent during development/tests.

Core first-party counters remain available without third-party configuration. Validation tests use an intercepted fake transport only. Reference: https://developers.google.com/analytics/devguides/collection/protocol/ga4/reference
